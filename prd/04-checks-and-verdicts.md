# 04. 점검과 판정

## 판정 4종
🔴 `VULNERABLE` 취약 · 🟡 `SUSPECTED` 의심(기능 손상·모호) · 🟢 `OK` 시험한 공격으로는 못 뚫음 · ⚪ `SKIPPED` 판단 불가(이유가 `detail`에 있음).
**⚪을 "안전"으로 읽으면 안 된다.**

## 마커로 판정한다
시드 데이터에 고유 문자열을 심고, 응답에 나타나면 그 데이터가 노출된 것이다.
| 종류 | 형식 | 용도 |
|---|---|---|
| 소유자 마커 | `ARGOS_<resourceId>_<org>_<hex6>` | 그 조직의 데이터가 응답에 있는가 |
| 비밀 마커 | `ARGOS_SECRET_<n>_<hex6>` | 민감 컬럼 값 노출 |
| 환경 카나리 | `ARGOS_ENV_<NAME>_<hex6>` | 앱 환경변수 노출 |
`hex6`은 설정 파일 해시로 시드해 **같은 설정이면 같은 값**(재현성). 어떤 출력에도 앞 6자(`ARGOS_`)만 싣는다.

## 매트릭스 칸
칸 하나 = "`persona`가 `target` 조직의 데이터를 요청했을 때". `persona.org == target`이면 **대조 칸**(소유자 본인 접근), 다르면 **공격 칸**. 익명은 첫 조직의 행을 요청한다.

`observed` 규칙: 2xx이고 **대상 조직의 마커**(어느 테이블 것이든)가 있으면 `allow`, 마커가 없으면 `allow-empty`. 401/403은 `deny`. 404는 `deny`이지만 소유자 본인의 404는 `error`. 그 밖은 `error`.
- **호출자 범위로 응답하는 목록**(경로에 `:param` 없음)에서 다른 조직을 요청해 그 조직의 마커가 없으면 `deny`다(올바른 동작). 있으면 `allow`(유출).
- 소유 행이 없는 리소스는 마커가 없으므로 거부 기대 칸의 2xx를 🔴로 본다.

`verdict`: 기대 `deny` + `allow` → 🔴, `allow-empty` → 🟡, `deny` → 🟢. 기대 `allow` + `allow` → 🟢, 그 외 → 🟡. `error`는 항상 ⚪.

## 점검 4종
| 점검 | 무엇을 | 🔴 조건 |
|---|---|---|
| `bola` | 다른 조직의 행을 읽을 수 있는가 | 공격 칸이 `allow` |
| `unauth` | 익명이 인증이 필요한 리소스를 호출할 수 있는가(`public` 제외) | 익명 칸이 `allow` |
| `sqli` | 쿼리 파라미터를 `"1"` → `"'"` → `"''"` 3단계로 시험 | 대조 2xx + `'` 5xx + `''` 2xx |
| `secrets` | (a) 응답 속 비밀 마커 (b) 환경 카나리 (c) 소스 하드코딩 | (a) 비소유자·익명 (b) 어떤 응답이든 (c)는 🟡만 |

`secrets (a)`에서 소유자 본인이 자기 비밀을 다시 받는 것은 🟡(`allowOwnerSecretRead: true`면 허용). `(b)`는 매트릭스가 보낸 응답만 검색한다(오류 유도 요청은 없음). `(c)`는 휴리스틱이라 🔴을 내지 않고, 값은 앞 4자 + 길이로만 보인다.

## "안전으로 보이지 않게" 하는 규칙 (가장 중요)
1. **대조 요청이 실패하면 거부를 신뢰하지 않는다.** 공격자 본인 또는 소유자의 정상 접근이 성공하지 않으면 `bola`/`unauth`는 ⚪. 만료된 토큰의 401이나 죽은 앱이 🟢으로 보이는 것을 막는다.
2. **증명된 유출은 대조 없이도 🔴**이다. 대조는 "OK" 쪽 결론에만 필요하다(로그인 없이도 새는 `export`가 대표).
3. `sqli`는 대조(`"1"`)가 2xx가 아니면 ⚪. 항상 500을 내는 앱을 🔴로 오판하지 않는다.
4. `secrets`의 "유출 없음(🟢)"은 2xx가 있거나, 모든 페르소나가 기대대로 거부된 리소스에만 인정. 아니면 ⚪.
5. 앱 기동 실패, 설정 오류는 "안전"이 아니라 **종료 코드 1과 로그 끝 50줄**.
6. 환경 변수를 덤프하는 응답은 증거에 **본문을 싣지 않는다**(`body withheld`). 호스트의 PATH 등이 증빙에 실리는 것을 막는다.
