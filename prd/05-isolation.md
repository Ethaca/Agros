# 05. 격리(sandbox)

Argos는 고객의 `target.start` 명령을 그대로 실행한다. 즉 **고객 코드를 실행하는 도구**이므로 격리가 보호 수준을 정한다.

## 두 가지 방식 (`target.isolation` 또는 `--isolation`)
| | `process` (기본) | `container` |
|---|---|---|
| 원본 보호 | ✅ 임시 복사본에서 실행, 원본 불변 | ✅ 동일 |
| 환경변수 | `PATH`, `HOME`(임시), `PORT`, `target.env`만 | 호스트 환경 **전혀 없음**. `PORT`, `target.env`, 카나리, `HOME=/tmp`만 |
| 네트워크 | ❌ 호스트 그대로 | ✅ 없음(`--network none`, 루프백만) |
| 파일 시스템 | ❌ 사용자 권한으로 호스트 접근 | ✅ 루트 읽기 전용, `/tmp`(tmpfs)와 `/app`(임시 복사본)만 쓰기 가능, 호스트 경로 안 보임 |
| 권한 | 호스트 사용자 | 비root(호스트 uid), `--cap-drop ALL`, `no-new-privileges` |
| 자원 제한 | ❌ | ✅ `--pids-limit`, `--memory`, `--cpus` |
| 경고 | "격리 없음: 신뢰하는 코드에만 실행" | `🔒 container isolation: <image> …` |

**`process`는 신뢰하는 코드에만 쓴다.** 고객 코드는 `container`로 돌려야 한다.

## 컨테이너 네트워크 설계
앱이 `127.0.0.1`에만 바인딩해도 동작해야 하고 외부로 나갈 수도 없어야 한다. 포트를 게시하려면 외부 접속을 열어야 하므로, **`--network none` + 호스트의 loopback TCP 포워더**를 쓴다. 연결마다 `docker exec -i <컨테이너> node -e <127.0.0.1:PORT로 파이프>`를 실행한다. 앱이 어디에 바인딩하든 되고, 게시 포트와 외부 접속이 없다.

## 실패는 항상 명시적
- 도커를 쓸 수 없으면 **오류(종료 코드 1)**. 호스트 프로세스로 조용히 대체하지 않는다.
- 이미지가 없으면 `docker pull`을 시도하고, 실패하면 `cannot pull image`.
- `image`/`memory`/`cpus`는 docker에 넘기기 전에 정규식으로 검증한다(`--privileged` 같은 옵션 주입 방지).

## 검증된 것 (프로브 앱으로 컨테이너 안에서 직접 시도)
외부 접속 실패(`ENETUNREACH`, DNS `EAI_AGAIN`), 인터페이스는 `lo`뿐, `/etc`·`/usr` 쓰기 실패(`EROFS`), `/tmp`·`/app` 쓰기 가능, 호스트 경로(`/Users` 등) 없음, uid=호스트 uid(≠0), `CapEff=0`, `NoNewPrivs=1`, 호스트 환경변수 없음. 같은 프로브를 기본 bridge 네트워크에서 돌리면 외부 접속이 **성공**하므로, 테스트가 인터넷 상태가 아니라 샌드박스를 검증한다.

## 결과 동등성
컨테이너와 프로세스의 `matrix.json`/`findings.json`은 데모 앱 2개에서 **바이트 단위로 같다**. 컨테이너 스캔 약 1.5초(프로세스 0.8초). `scan-meta.json`에 `isolation`과 `image`가 기록된다.

## 한계
- 이미지에 **`node`가 있어야** 한다(포워더). Python 등 다른 런타임 앱은 별도 처리가 필요하다.
- 의존성은 **컨테이너 플랫폼(Linux)에서 동작해야** 한다. 복사본의 `node_modules`를 그대로 쓰므로 macOS용 네이티브 모듈은 실패한다(순수 JS는 문제없음). 컨테이너 안 설치 단계는 아직 없다.
- `/app`(임시 복사본)은 쓰기 가능하다. 앱이 DB를 쓰기 때문이며, 원본이 아니라 버리는 복사본이다.
- 연결마다 `docker exec`를 띄우므로 요청이 매우 많은 시험에는 느려질 수 있다(keep-alive로 완화).
- 도커 데몬이 호스트 권한으로 동작하는 것 자체는 신뢰 경계 밖이다.
- 정적 스캔과 `fix` 제안 생성은 **원본 소스를 읽기 전용**으로 읽는다. 원본을 바꾸는 것은 `fix --apply`뿐이다.
