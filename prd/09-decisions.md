# 09. 결정 기록

각 항목: 결정 → 이유 → 대가.

**블랙박스 + 설정 기반** → 5시간에 만들 수 있고 언어에 무관. → 설정에 없는 라우트는 시험 못 한다(범위를 `scan-meta.json`에 명시).

**마커로 노출을 판정** → 응답에 데이터가 있는지가 상태 코드보다 정확하다(200이어도 비어 있을 수 있고, 404가 은닉일 수 있다). → 시드가 필요하고 SQLite만 지원.

**조직 마커는 어느 테이블 것이든 인정** → `dataset-tasks`처럼 라우트가 가리키는 테이블과 응답 행의 테이블이 다를 수 있다. 시드도 `<x>_id`를 같은 조직의 행에 연결한다.

**호출자 범위 목록은 `deny`** → 목록이 자기 행만 주는 것은 정상이다. 다른 조직의 마커가 없으면 막힌 것으로 본다. → 마커가 있으면 유출(🔴).

**증명된 유출은 대조 없이 🔴, "OK"는 대조가 있어야** → 양성은 그 자체가 증거이고, 음성만 환경(죽은 앱·토큰)에 속을 수 있다.

**⚪을 두고 "안전"으로 보이지 않게** → 거짓 안전이 가장 해롭다. 앱이 안 뜨면 종료 코드 1.

**환경 덤프 응답은 본문을 증거에 싣지 않음** → 예시를 만들다 호스트 `PATH`/홈 경로가 증거에 섞인 것을 발견. 리포트가 증거를 옮기면 증빙 문서로 새는 문제였다.

**정적 스캔(c)은 🟡만** → 휴리스틱이라 확신할 수 없다. 시드·테스트·fixtures·examples·argos 설정은 기본 제외(오탐 방지), 값은 앞 4자 + 길이.

**`fix`는 제안별 누적 검증** → 처음에는 전체를 한꺼번에 적용해 하나만 실패해도 전부 거부했다. 인증 없는 라우트의 소유자 검사 하나가 나머지를 막으므로 제안 단위로 바꿨다.

**자동 수정 범위를 좁게** → 틀린 자동 수정이 더 해롭다. 모든 수정은 같은 매트릭스 재검증을 통과해야 채택되고, 원본은 `--apply`일 때만 바뀐다.

**컨테이너 네트워크: `--network none` + `docker exec` 포워더** → 데모 앱은 `127.0.0.1`에만 바인딩한다. 포트 게시는 외부 접속이 필요하다. → 연결마다 `docker exec`를 띄운다(이미지에 `node` 필요).

**컨테이너는 옵트인(기본 `process`)** → 도커 없는 환경과 기존 테스트를 깨지 않는다. → **고객 코드는 반드시 `--isolation container`**로 돌려야 한다는 안내가 필요하다.

**도커가 없으면 오류(자동 대체 없음)** → 격리를 요청하고 조용히 호스트에서 실행하면 보호가 없는데 있는 것처럼 보인다.

**`scan-meta.json`을 따로 둠** → 리포트가 해시·시각·범위를 직접 계산하지 않게 한다. 격리 방식도 증빙의 일부다.

**출력 예시를 테스트가 지킴** → 문서가 코드와 어긋나지 않게(S12, 스키마·해시 테스트).
