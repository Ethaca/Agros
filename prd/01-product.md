# 01. 제품 개요

## 한 줄
> 외부 벤더에게 민감한 데이터와 작업을 맡길 때, 권한이 **설정되어 있다**가 아니라 **공격해서 증명됐다**를 보여 준다.

Argos는 실행 중인 API를 여러 페르소나(벤더 A, 벤더 B, 익명)로 **실제로 공격**해서 "누가 무엇을 볼 수 있는가"를 **기대 vs 실제 접근 매트릭스**로 증명하고, 결과를 **증빙 문서**로 내며, 설정은 **AI가 초안**을 쓴다.

## 세 기둥
| 기둥 | 뜻 | 상태 |
|---|---|---|
| PROVE | 페르소나 × 리소스 공격, 점검 4종, 접근 매트릭스 | ✅ 구현 |
| VOUCH | 증빙 리포트(증빙 헤더, 매트릭스, 한계 문구) | ✅ `argos report`(첫 버전, A 구현이 들어오면 교체 가능) |
| PLUG | `argos init`: 저장소를 읽어 설정 초안 생성, 기동·로그인 검증 | 🔶 v1 구현(정적 규칙, express-sqlite). LLM 초안·`--update`는 아직 |

후순위: TRACE(카나리 발급·식별·오염 탐지). 최하위: PDF 내보내기·전송. 이번 범위 밖.

## 사용자 흐름
```
argos init <repo>   → argos.config.yaml 초안 + 기동·로그인 검증 + 확인 목록   ✅ v1(LLM 없는 정적 규칙)
argos scan          → out/matrix.json, findings.json, scan-meta.json        ✅
argos fix [--apply] → 수정 제안, 같은 매트릭스로 재검증, 채택분만 적용       ✅
argos report        → out/report.md (증빙 헤더 + 한계 문구)                  ✅
argos ci            → 위 전부를 한 번에 + 수정 PR(--pr) + PR 본문              ✅
```
CI 연동은 GitHub Actions 예시(워크플로가 `scan`, `report` 실행 후 PR 코멘트)까지만 계획. 웹훅 서버·GitHub App은 범위 밖.

## 확정된 결정 (SPEC 기준)
- **블랙박스 + 설정 기반.** 코드에서 경로를 추적(Access Path IR)하지 않는다. 시험할 라우트와 기대 접근은 설정이 정한다. 장점은 구현이 작고 언어에 무관하다는 것, 한계는 **설정에 없는 경로는 시험하지 않는다**는 것이다.
- **기본 모드는 `report`(비차단).** 🔴이 있어도 종료 코드 0. `mode: block`이면 🔴이 있을 때 2.
- **판정은 실행 증거로만.** AI는 설정 초안과 설명·수정 제안에만 쓰고 판정을 낮추지 않는다.
- **"API 키 유출"의 정의:** (a) 응답 속 민감 필드 노출, (b) 환경 비밀 노출, (c) 소스 하드코딩.
- 개발은 5시간 범위로 가정, 개발자 2명(A: 데모·리포트·init, B: 코어·점검).

## 말하면 안 되는 것
- "보안을 보증한다", "오염/유출이 없음을 증명한다". 🟢은 **시험한 공격으로는 못 뚫었다**는 뜻일 뿐이다. 리포트의 한계 문구가 이를 명시한다.
- 구매 의사는 미검증 가설이다. 시연에서도 가설임을 숨기지 않는다.
